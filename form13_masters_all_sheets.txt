
=== SHEET: How to use ===
ODeX Form 13 — customer master workbook | 
This workbook is embedded in the Form 13 API document. Double-click the Excel icon in the Word file to open it. | 
Testing is on the PRODUCTION system. Use only demo users, and only these shipping line codes: DEMO, DEBET, DEALP. | 
DEMO = general shipping lines. DEBET = MSC configuration. DEALP = Hapag-Lloyd configuration. | 
Do not send any other bnfCode during testing. A request with a live line code is a real production Form 13. | 
Where a code exists more than once, send the value shown on the Form 13 screen, not an inactive or duplicate master row. | 
Vessel, POD, shipper and haulier lists change. Refresh them from the APIs and from the Form 13 screen. Do not hard-code yesterday's vessel. | 
Sheets in this workbook are the code lists the API expects. Attachment titles, issue-to, haulier and shipper still depend on port, terminal and line. | 

=== SHEET: Demo shipping lines ===
Name shown for testing | API field bnfCode | What it exercises | Allowed during production testing
DEMO | DEMO | General shipping line behaviour. | Yes. This is the only general-line code for testing.
DEBET | DEBET | MSC configuration. Shipping instruction number is handled at container level. | Yes. Use this instead of the live MSC code.
DEALP | DEALP | Hapag-Lloyd configuration. Booking-copy BL number and shipping-instruction check apply, except reefer cargo. | Yes. Use this instead of the live Hapag-Lloyd code.

=== SHEET: Shipping line rule ===
Rule | What the customer sends
Which code | bnfCode is the shipping line code (SCAC) of the line selected on the Form 13 screen.
Duplicates | If the same line name or the same code exists more than once in master, send the name and code that appear on the Form 13 dropdown. Ignore inactive rows and rows that are not enabled for Form 13.
How to confirm | The Vessel Master API returns bnfCode on every vessel. That value is the same code to send in saveF13 for that vessel.
Testing | On this production test kit the only permitted codes are DEMO, DEBET and DEALP. Live production codes are shared after UAT sign-off.
Invalid code | Any other value returns Beneficiary Code is invalid.

=== SHEET: Issue to ===
Rule | Detail
API field | issueTo
Where it is mandatory | Form 13, every terminal except NSIGT, NSICT, MICT, IGT and CCTL.
Where it is omitted | Leave it blank for NSIGT, NSICT, MICT, IGT and CCTL.
Which value | Send the code shown in the Issue To dropdown on the Form 13 screen for that line, port and terminal. The usual descriptions are Shipper and CHA.
Duplicates | If a value is listed twice, send the code that is shown on the screen.
Invalid value | Error (1017): issueTo is invalid.

=== SHEET: Haulier ===
Rule | Detail
API field | haulier, inside each container object.
What to send | The haulier code, not the transporter name. Use the code shown on the Form 13 screen for that terminal and port.
When required | Form 13, status Requested, origin is not Dock stuffed (C), and the terminal has an active haulier list.
When not required | Origin C (dock stuffed), or the terminal has no haulier master.
Invalid code | Error (1053) - Haulier Code is invalid.
How the list is kept | Active rows for the terminal and location. Adani terminals are refreshed from the terminal transporter feed. Copy the code from the screen on the day of the request.
Duplicates | If the same transporter appears twice, send the code shown on the screen.

=== SHEET: Shipper ===
Situation | shipperNm | shipperCd | What ODeX does
Ordinary terminal | Mandatory. Free text, max 100. Letters, numbers and , . / _ - | Send the code you hold. It is not checked against a terminal shipper list. | The name is stored as sent.
Terminal integrated with the shipper master (Adani-family terminals that have a terminal API and a liner code) | Mandatory. Must match an active shipper for that port and terminal, by name or by code. | Mandatory. Must match the same master row. | ODeX replaces both fields with the name and code stored on the master, which are the values shown on the Form 13 screen.
No match on an integrated terminal | Rejected | Rejected | Error (1024) - Shipper Name or Shipper Code is invalid.
Tuticorin terminal DBGT | Still required | Still required | shipperCity is also mandatory.
Duplicates | Use the name shown in the shipper dropdown. | Use the code shown beside that name. | Do not send an old spelling or an inactive code.

=== SHEET: Terminal login ===
Rule | Detail
API field | terminalLoginId. Max 200. Letters, numbers and , . / _ -
Mandatory | 1) Ports where the Form 13 screen shows Terminal Login Id as mandatory (exception ports such as Chennai, Kattupalli, Ennore, Paradip and Kolkata). 2) Any terminal whose master flag is Mandatory (M). 3) Mundra terminals ADANI, AMCT, AICTPL, ACMTPL and AMCT2.
Adani check | On an Adani-integrated terminal the value must exist as a CHA code in the terminal cross-reference for that terminal and port. Otherwise the terminal login id is rejected.
Value to send | Send the code (XREF_VAL), not the company description. If you do not have an id, the Form 13 screen says to enter ALL_CHA / MUNCUST. At Hazira the screen says to enter OTH.
On-wheel / DPE | For DPE shipments select origin W and enter the CHA code in terminal login id, other than OTHR.
Duplicates | If one company has more than one code, send the code shown on the Form 13 screen.
Master sheet | The next sheet is the AMCT CHA cross-reference from the current master extract. Other terminals use the same columns. Take the live code from the screen for the terminal you are filing.

=== SHEET: Vessel refresh ===
Step | fromTs | Result
First load | A timestamp far in the past, for example 2000-01-01 00:00:00 | One response with every vessel created or updated since that time. Store the greatest lastUpdatedOn.
Daily job | The greatest lastUpdatedOn saved from the previous call | Only vessels added or changed since that time. Merge them into the local vessel table by line, port, vessel name and VIA.
On request | Same as the daily job, or repeat the full load | Run this before a filing day if the line has opened a new vessel or changed a cut-off.
Do not | A date-only value such as 2026-10-16 | Rejected. fromTs must be YYYY-MM-DD HH:MM:SS.
